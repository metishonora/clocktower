# #232 복합 게임 인수 묶음

47종의 실제 능력·효과를 다섯 게임에 배치했다. 각 게임은 실제 입력으로 만든 첫날 밤부터 여러 밤과 종료까지 이어진다. 동시에 성립하지 않는 선택은 Undo 또는 명시한 저장 지점 불러오기로 확인한다. 후보 풀에만 포함된 캐릭터를 검증 완료로 세지 않는다.

## 진행 순서

1. **G01 → G02 → G03 → G04 → G05** 순서로 진행한다. 각 링크의 좌석표와 절차를 사용한다.
2. 앱 첫 화면에서 **Custom Scenario 선택 → JSON에서 불러온다**를 누르고 해당 `Gxx-start.game.json`을 선택한다. **마도서 이어 쓰기**를 누른다.
3. 각 절차의 굵은 사례 ID에서 기대 결과를 확인하고 `results.csv`에 통과/실패/미확인/해당 없음을 기록한다. 기기·브라우저, 관찰, 실패 이유도 함께 적는다. 자동화 통과가 사용자 인수나 실기기 통과를 대신하지 않는다.

| 게임 | 함께 확인할 내용 | 절차 |
| --- | --- | --- |
| G01 뒤바뀐 증언 | 시작 정보, 주정뱅이·수학자, 은둔자 등록, 집사·유령표, 성자 | [G01](G01.md) |
| G02 죽음의 계승 | 보호·공격, 성결자·장의사, 집착 처형, 임프 승계, 마녀·이발사·연인 | [G02](G02.md) |
| G03 거짓의 계산 | 보르톡스 거짓 정보와 해제, 낮 정보, 쌍둥이, 변종·얼뜨기, 서로 다른 종료 | [G03](G03.md) |
| G04 건너간 악마 | 철학자, 순서 밖 시작 정보, 현자 징크스, 팡 구 이동·탕녀, 뱀 조련사 | [G04](G04.md) |
| G05 죽어도 남는 힘 | 유지되는 죽은 하수인 능력, 후속 중 복원, 악마 변경, 노 다시 중독·해제 | [G05](G05.md) |

## 공통 조작

- **선택:** 해당 행동의 대상 선택을 열고 번호를 선택한 뒤 선택 확정을 누른다. 캐릭터·등록·시장 판단 등이 적혀 있으면 같은 선택 화면에서 입력한다. 숫자나 예/아니오의 명시적 전달값이 없으면 앱의 정상 계산값을 사용한다.
- **공개:** 정보 공개를 누르고 플레이어용 화면을 확인한다. “확인했으면 눈을 감으세요”로 닫고 다음으로 진행해 확정한다. 준비·선택만으로 사례를 완료 처리하지 않는다.
- **결과·정체 통지:** 공격 결과와 새 캐릭터 통지가 있으면 차례로 확인한다. 비공개 통지를 대상 플레이어에게만 공개하고 닫은 뒤 다음 행동으로 간다. 시작 시 속임수 선택을 먼저 요구하면 좌석표 아래의 세 캐릭터를 선택한다.
- **저장·복원:** 저장 / 불러오기에서 JSON을 내보내고 새로고침한다. 공개 화면이 저절로 열리지 않는지 확인한다. 내보낸 파일을 다시 불러와 마도서 이어 쓰기를 누르고 같은 미완료 행동을 계속한다. 각 `*-pending.game.json`에서도 반복한다.
- **Undo:** 최근 행동 되돌리기에서 대상 묶음을 확인하고 실행한다. 공격과 즉시 후속은 함께, 뒤의 독립 정보 행동은 별도로 되돌아가야 한다.
- **중간 시작:** 각 절차 맨 아래의 파일을 불러오면 해당 지점부터 시작할 수 있다. 분기 후에 이전 파일로 돌아가라는 지시를 빠뜨리지 않는다.
- **시나리오 작성:** `Gxx.scenario.json`은 배역을 배정하기 전의 후보 풀과 두 밤 순서다. 최종 검토에서 밤 순서로 돌아가 첫날 밤을 이동한 뒤 이후 밤이 그대로인지 확인한다. 저장·재불러오기·기본값 복원을 확인한다. 실제 진행용 파일은 다시 원본을 불러온다.
- **직업·PDF:** 같은 게임의 시나리오와 게임 파일 각각에서 직업 일람을 연다. 내용이 같고 플레이어 이름·실제 배역·중독·속임수가 없는지 확인한다. 징크스는 G01 1개, G02 0개, G03 0개, G04 2개, G05 1개다. G05의 미배정 은둔자도 후보 풀의 현자 징크스를 표시해야 한다.

## 결과와 범위

[coverage.md](coverage.md)는 캐릭터→사례 연결, [manifest.json](manifest.json)은 명령·기대·사건 관찰과 파일 연결을 담는다. 주요 분기 목록은 추가 검토 대상이며 연결 사례와 기존 테스트의 검증 범위를 넘어서 통과로 해석하지 않는다. 전체 조합을 전수 검사한 묶음은 아니다.

실제 iPhone/iPad Safari, 홈 화면 설치 후 오프라인 재시작, 운영체제 인쇄·PDF 저장, 터치 조작은 **미확인**이다. 자동 WebKit/화면 크기 검증과 구분한다. PDF의 긴 문구·전체 47종 페이지 나눔은 기존 `scenarioReference.spec.ts` 회귀 묶음에 있다.

사용자 승인 전에는 #232를 완료하지 않는다. 발견한 문제는 사례 ID와 실패 직전 내보낸 게임 파일을 함께 남긴다. 자동화에서 발견한 두 규칙 결함은 `docs/testing/issue-232-defects.md`에 재현과 수정 근거를 기록했다. 이전 잘못된 사건이 포함된 저장 파일의 migration은 이 이슈 범위 밖이다.

## 재실행

저장소 루트에서 실행한다. WASM 빌드와 의존성 설치가 선행되어야 한다.

```sh
pnpm --dir web exec vitest run --config vitest.custom.config.ts test/custom/issue232Acceptance.test.ts test/custom/issue232Archive.test.ts
pnpm --dir web exec playwright test --config playwright.acceptance.config.ts --workers=1
```

새 캐릭터 추가 때의 빠른 규칙 회귀는 G01·G02·G05로 시작하고, 최종 인수에서는 다섯 게임과 전체 커스텀 테스트를 실행한다. 파일을 다시 생성할 때만 다음 명령을 사용한다. 수동 결과는 별도 복사해 보존한다.

```sh
ISSUE232_WRITE=1 pnpm --dir web exec vitest run --config vitest.custom.config.ts test/custom/issue232Acceptance.test.ts
```
