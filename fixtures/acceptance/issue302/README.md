# 이슈 302 인수 테스트

`festival.scenario.json`은 리뷰에 사용한 ‘만인의 축제’ 원본이다. 아래 게임 파일은 동일한 직업 풀과 밤 순서의 실제 명령 기록을 문제가 발생하기 직전까지 저장한 것이다. 커스텀 시나리오에서 파일을 불러온 뒤 **마도서 이어 쓰기**를 선택한다.

## 달의 자손과 시장

`moonchild-mayor.game.json`: 낮에 죽은 6번 달의 자손이 1번 시장을 선택했고, 다음 밤의 처리 직전이다.

1. **시장 사망 판정**을 누른다. 결과를 고르기 전에는 사망을 확정할 수 없어야 한다.
2. **다른 플레이어가 대신 사망**을 고르고 2번 화가를 선택해 확정한다.
3. 마도서 결과에서 1번의 생존과 2번의 사망을 확인한다.
4. 새로고침해도 같은 결과가 보여야 한다. Undo하면 선택 직전으로 돌아가야 한다.
5. 파일을 다시 불러와 **시장이 사망**을 선택하면 1번이 죽어야 한다.

Core 회귀 테스트는 수도승이 보호한 대상의 전가 사망, 어릿광대의 방어, 이미 죽은 대상, 중독된 시장, 잘못된 전가 입력, 이전 입력 생략 기록도 검증한다.

## 밤 승패 판정

`terminal-imp.game.json`: 3번 어릿광대·4번 암살자·5번 임프만 살아 있고, 어릿광대의 최초 사망 방지는 이미 소모됐다.

1. 임프가 3번을 공격한다.
2. 공격 결과를 확인하고 **진행으로 →**를 누르면 **악 진영 승리**가 떠야 한다.
3. 암살자 단계나 새벽 확인을 거치지 않고 종료를 확인할 수 있어야 한다.
4. 저장 후 새로고침해도 악의 승리가 유지돼야 한다. Undo하면 마지막 공격과 종료 확인이 함께 취소돼야 한다.

악마가 죽어도 정상적인 즉시 계승으로 새 악마가 생긴 경우에는 게임을 끝내지 않는지 Core에서 별도로 검증한다.

기존 달의 자손 기록에 시장 선택 입력이 없으면 당시의 직접 사망 결과를 유지한다. 이미 성립한 승패 뒤로 행동을 더 저장한 과거 버그 기록은 자동으로 승자를 바꾸지 않고 재생 오류로 거절한다.
