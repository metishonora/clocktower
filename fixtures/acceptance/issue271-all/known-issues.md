# 수정된 B20과 남은 인수 항목

2026-10-10: **B20 확정 오류 수정 및 자동 회귀 통과**. 실제 기기의 사용자 인수와 세 구현을 합친 빌드의 검증은 남아 있다.

## B20 재현 파일과 정상 결과

서버: [BMR 검토 서버](http://100.91.205.43:10271/clocktower/)

파일: [moonchild-night-poisoned.game.json](bmr/moonchild-night-poisoned.game.json)

명단: 1 화가 · 2 군인 · 3 어릿광대 · 4 처단자 · 5 시장 · 6 달의 자손 · 7 은둔자 · 8 독살범 · 9 임프.

파일에 이미 저장된 진행:

1. N2에 임프가 6번 달의 자손을 죽인다.
2. D2 사망 발표 후 달의 자손이 살아 있는 선한 1번 화가를 공개 선택한다.
3. N3에 독살범이 죽은 6번 달의 자손을 중독시킨다.
4. 임프는 정상 군인 2번을 공격하여 죽이지 못한다.
5. 현재 Core 차례는 달의 자손이고, 불러온 화면에는 직전 임프 결과가 먼저 열린다.

사용자 조작:

1. 파일을 불러와 **마도서 이어 쓰기**를 선택한다.
2. 임프 결과를 **진행으로 →**로 닫는다.
3. 달의 자손 차례에서 **확정**을 누른다.
4. 1번 화가 생존과 새벽 이동을 확인한다. 추가 결과 화면은 없다.
5. 저장 완료 후 새로고침·JSON 내보내기/재불러오기·Undo를 확인한다.

## 원인과 수정

이전에는 현재 밤의 중독을 확인하려고 행동의 `actionCause`를 지웠다. 이로 인해 오작동 근거에 담긴 행동 출처가 확정하려는 원래 행동과 달라져, reducer가 `INVALID_FIRST_NIGHT_ACTION_PROVENANCE`로 거절했다. 입력 누락이나 무효 인수 파일의 문제가 아니었다.

현재 밤의 중독 상태를 확인하는 함수를 분리해, 원래 사망 원인과 행동 출처를 보존한다. 사망 당시 상태를 사용하는 다른 캐릭터의 기존 경로는 유지한다. GameFile 스키마 변경은 없다.

## 남은 인수와 UX 논의

- 사용자·실기기: 모든 상세 분기, 정보 기록 재공개, Safari·모바일·오프라인, 낮 자유 행동 버튼과 순서 목록의 겹침.
- 통합: BMR·귀족·골렘 세 작업트리를 합친 최종 빌드 회귀.
- 별도 UX 결정: 한 명 선택 중 다른 좌석으로 바로 바꾸기, 처형 버튼 문구 통일, 골렘→사랑꾼 후속을 마도서에서 이어 처리하기, 닫은 결과 패널을 새로고침 후에도 숨길지 여부.

위 UX 항목은 이번 오류 수정에 포함하지 않았다. 현재 결과 패널 복원 동작을 기준으로 각 파일의 시작 화면을 문서에 표시했다.
