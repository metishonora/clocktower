# #271 캐릭터 8종 인수 테스트

2026-10-09 기준. 이번 이슈에서 구현한 BMR 6종과 이후 추가한 귀족·골렘을 대상으로, 행동 직전부터 시작하는 게임 파일 35개와 조작·기대 결과를 준비했다.

**현재 알려진 실패 1건:** 달의 자손이 공개 선택 후 밤에 중독되면 확정이 오류로 막힌다. [B20 재현과 기대 결과](known-issues.md)를 별도로 확인한다. 파일 불러오기 성공과 캐릭터 동작 인수 통과는 구분한다.

## 1. 파일과 검토 서버

ZIP을 풀고 아래 서버에서 해당 폴더의 개별 .game.json 파일을 불러온다. 구현이 세 작업트리에 나뉘어 있어 그룹마다 서버가 다르다. 세 그룹을 하나로 합친 빌드의 통합 인수는 아직 남아 있다.

| 그룹 | 검토 서버 | 파일 | 상세 시나리오 |
| --- | --- | ---: | --- |
| BMR 6종 | [BMR 검토 서버](http://100.91.205.43:10271/clocktower/) | bmr/ · 20개 | [BMR 조작·기대 결과](bmr.md) |
| 귀족 | [귀족 검토 서버](http://100.91.205.43:11090/clocktower/) | noble/ · 6개 | [귀족 조작·기대 결과](noble.md) |
| 골렘 | [골렘 검토 서버](http://100.91.205.43:11786/clocktower/) | golem/ · 9개 | [골렘 조작·기대 결과](golem.md) |

검토 서버는 Tailscale 연결이 있는 기기에서 접속한다. 위 링크는 관리자에서 반환한 주소이며 인수 검토 동안 유지한다.

## 2. 불러오기

1. 지정 서버에서 Custom Scenario를 선택한다.
2. **파일에서 불러온다** → 사례의 .game.json 파일 → **마도서 이어 쓰기**.
3. 직전 행동 결과가 복구되어 있으면 **진행으로 →** 또는 **다음 →**를 눌러 표에 적힌 차례로 이동한다.
4. 상세 시나리오의 좌석 번호와 입력을 따른다. 새 파일의 P1, P2 등은 좌석과 같은 번호의 테스트 이름이다.
5. 다른 분기를 비교할 때는 원본 파일을 다시 불러온다. 일부 파일은 같은 테스트 게임 ID를 공유하므로 보존할 결과는 먼저 JSON으로 내보낸다.

모든 파일은 GameFile v5이며 실제 Core 명령으로 생성한 이벤트를 담고 있다. 전체 좌석·직업·시작 상태·파일 해시는 [manifest.json](manifest.json)에 있다.

## 4. 공통 인수

- [ ] 진행자 화면의 선택·판정과 플레이어에게 공개하는 정보가 구분된다. 공개 화면에는 취급·실제 직업·중독 등 비공개 정보가 섞이지 않는다.
- [ ] 각 행동 후 저장 완료를 기다려 새로고침하고, 다음 차례·생사·사용 토큰·전달 정보가 유지되는지 확인한다.
- [ ] JSON 내보내기 → 다시 불러오기 후 같은 상태와 기록으로 이어진다.
- [ ] 되돌리기 확인 창의 대상 행동을 확인하고 Undo한다. 그 행동의 사망·사용·예약·취급 선택이 함께 복원된다. 여러 후속 행동을 이미 확정했다면 해당 행동까지 순서대로 되돌린다.
- [ ] 할머니·귀족은 기록에서 다시 공개해도 같은 정보를 보여 준다.
- [ ] 휴대전화 세로·태블릿·데스크톱에서 좌석, 결과 상자, 확정 버튼이 잘리지 않는다.
- [ ] 실제 Safari/모바일 기기와 오프라인 재진입을 별도로 확인한다.

## 5. 결과 기록과 완료 기준

[results.csv](results.csv)는 파일 단위 결과표다. 사용자·실기기 칸은 모두 NOT_RUN으로 시작한다. 분기가 둘 이상인 사례는 상세 문서의 모든 분기를 확인한 뒤 PASS로 바꾸고, 기기·브라우저·실패 분기는 notes에 적는다.

- 파일 재생·JSON 왕복: **35/35 통과**.
- 실제 앱 컨트롤러의 파일 불러오기·저장 복원: **35/35 통과**.
- 공개 WASM 명령으로 다음 결과 검증: **23건 중 22 통과, B20 1건 실패**.
- 사용자 인수·실기기 인수: **미실행**.

검증 범위와 재현 명령은 [검증 기록](verification.md)에 있다. 자료 생성이나 자동 테스트 통과를 사용자 인수 완료로 간주하지 않는다. B20 수정, 상세 사례 확인, 세 구현의 통합 빌드 회귀까지 끝나야 전체 완료를 판단할 수 있다.
