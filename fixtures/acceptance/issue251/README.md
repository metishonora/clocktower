# #251 전도사·객실 청소부 확인

프로토타입이 아니라 프로덕션 Custom Scenario에서 사용하는 게임 파일입니다.
`Custom Scenario 선택 → 파일에서 불러온다 → 게임 파일 선택 → 마도서 이어 쓰기`로 시작합니다.

각 항목은 파일을 **새로 불러온 상태**에서 시작합니다. #251 구현이 올라간 검토 서버를 사용하세요. 아직 병합·배포되지 않은 기능이므로 기존 배포 서버에서는 파일을 불러오지 못할 수 있습니다.

| 파일 | 확인 방법 |
| --- | --- |
| [preacher.game.json](preacher.game.json) | 전도사 대상 선택 → 6번 하린(독살범) → 선택 확정. 마도서에서 통지 안내 → 공개(전도사 아이콘·이름, 행동자 신원 없음) → 닫으면 ‘하수인 선택’ → 진행으로. 독살범은 행동하지 않으며 ‘능력 없음’ 토큰이 표시됩니다. 2번을 고르면 공개 없이 ‘아무 일도 없음’입니다. |
| [chambermaid.game.json](chambermaid.game.json) | 객실 청소부가 1번 민지와 3번 서윤 선택. 진실 2명: 야경꾼은 사용을 거절했지만 깨어났고, 수학자는 징크스로 깨어날 예정입니다. 근거는 읽기 전용입니다. 공개에는 두 사람·2명·깨어남만 표시됩니다. |
| [chambermaid-poisoned.game.json](chambermaid-poisoned.game.json) | 같은 대상을 고른 뒤 숫자 입력. 7처럼 2보다 큰 정수와 진실인 2도 전달할 수 있습니다. 음수·소수는 불가합니다. |
| [chambermaid-vortox.game.json](chambermaid-vortox.game.json) | 같은 대상을 고른 뒤 거짓 숫자 입력. 7은 허용되며 진실인 2는 불가합니다. |

## 직접 확인 절차

### P01 — 전도사: 하수인 통지와 결과

1. `preacher.game.json`을 불러옵니다. 전도사에서 `대상 선택`을 누릅니다.
2. **6번 하린 · 독살범**을 선택하고 `선택 확정`을 누릅니다.
3. 진행 탭으로 이동하지 않고 마도서 안에 **전도사 통지 / 6번 하린 / 공개**가 나타나는지 확인합니다.
4. `공개`를 누릅니다. **이 캐릭터가 당신을 선택했습니다 → 전도사 아이콘 → 전도사**가 표시되고, 전도사 플레이어의 이름·좌석은 나타나지 않아야 합니다.
5. 공개를 닫으면 **선택 대상 / 적용 결과: 하수인 선택 / 진행으로 →**가 나타나야 합니다.
6. 진행으로 돌아가 악팀 초기 정보를 진행합니다. 악마 속임수는 **군인·시장·성결자**를 고릅니다. 독살범의 독 대상 선택은 생략되어야 합니다.
7. 마도서에서 6번을 열면 전도사 아이콘의 **능력 없음** 원형 토큰이 있어야 합니다. 전도사에게 명중 결과를 공개하는 화면은 없어야 합니다.

### P02 — 전도사: 비하수인과 되돌리기

1. 같은 파일을 다시 불러와 **2번 태오 · 객실 청소부**를 선택합니다.
2. 별도 통지·공개 없이 **적용 결과: 아무 일도 없음**이 나타나고, 2번에게 전도사 토큰이 생기지 않아야 합니다.
3. 되돌리기로 전도사 선택을 취소하고 **6번 하린**을 선택하면 P01의 통지가 나타나야 합니다.

### P03 — 통지 대기 중 저장·복원

1. 같은 파일에서 6번을 선택한 뒤 **전도사 통지 안내가 뜬 상태**로 새로고침합니다.
2. 플레이어 정보가 자동으로 공개되지 않고 통지 안내부터 복구되는지 확인합니다.
3. 공개 후 닫으면 결과를 확인하고 진행으로 돌아갈 수 있어야 합니다. 중복 토큰은 없어야 합니다.

### C01 — 객실 청소부: 진실·근거·공개

1. `chambermaid.game.json`을 불러와 `두 명 선택`을 누릅니다.
2. **1번 민지 · 야경꾼**, **3번 서윤 · 수학자**를 고르고 `선택 확정`을 누릅니다.
3. 진행 화면의 **진실은 2명**이어야 합니다. `판정 근거`를 열면 야경꾼은 **깨어남**, 수학자는 **깨어날 예정**으로 표시되어야 합니다. 수정 버튼·체크박스가 없어야 합니다.
4. `정보 공개`에는 **1번 민지 · 3번 서윤 중 / 2명 / 깨어남**이 크게 표시되어야 합니다. 직업, 진실/거짓 여부, 누가 깨어났는지는 노출하지 않습니다.
5. 공개를 닫고 다음 단계로 진행합니다.

### C02 — 다른 능력 통지·악팀 초기 정보 제외

1. `preacher.game.json`에서 P01처럼 독살범을 선택하고 악팀 초기 정보를 끝냅니다.
2. 객실 청소부 차례에 **6번 하린 · 독살범**, **7번 서준 · 임프**를 선택합니다.
3. **진실은 0명**이어야 합니다. 독살범은 전도사 통지와 악팀 초기 정보만 받았으며 자신의 능력은 상실했고, 임프는 첫날 밤 악팀 초기 정보만 받았습니다.
4. 객실 청소부를 확정한 뒤 수학자의 진실도 **0**이어야 합니다. 능력 상실로 시도하지 않은 독살범 행동을 오작동으로 세지 않습니다.

### C03 — 중독: 숫자 입력

1. `chambermaid-poisoned.game.json`을 불러와 1번과 3번을 선택합니다. 진실은 **2명**입니다.
2. 전달 숫자가 선택 버튼이 아닌 입력란인지 확인합니다.
3. **7**을 입력해 공개하면 **7명**이 표시되어야 합니다. 0–2로 제한하면 실패입니다.
4. 파일을 새로 불러와 **2**도 공개 가능한지 확인합니다. 중독에서는 진실 전달도 가능합니다.
5. 음수·소수·빈 입력은 공개할 수 없어야 합니다.

### C04 — 보르톡스: 거짓 숫자 입력

1. `chambermaid-vortox.game.json`을 불러와 1번과 3번을 선택합니다. 진실은 **2명**입니다.
2. **2**를 입력하면 진실이라 공개가 차단되어야 합니다.
3. **7**로 바꾸면 `거짓 정보 공개`가 가능하고, 공개 화면에는 **7명**만 표시되어야 합니다.
4. 음수·소수·빈 입력은 허용되지 않습니다.

### C05 — 대상 변경 및 저장 파일 왕복

1. 정상 객실 청소부 파일에서 1번과 3번을 고른 뒤, 공개 전에 `대상 변경`을 누릅니다.
2. 3번을 해제하고 **4번 도현 · 화가**를 고릅니다. 1번과 4번의 진실은 **1명**이어야 합니다.
3. 공개·확정 후 `저장 / 불러오기`에서 게임을 저장하고, 그 파일을 다시 불러옵니다.
4. 확정된 객실 청소부 행동과 전달 정보가 유지되어야 합니다. 되돌리면 해당 행동을 다시 진행할 수 있어야 합니다.

## 확인 범위와 결과 기록

- 위 P01–P03, C01–C05는 **사용자 직접 확인 대기**입니다. 자동 테스트 통과를 사용자 인수 통과로 표시하지 않습니다.
- 실패 제보: `항목 ID / 실제 결과 / 스크린샷 또는 해당 시점 저장 파일`을 #251에 남깁니다.
- Rust 268개, 웹 369개, 390px·1280px 브라우저 8개와 프로덕션 빌드는 통과했습니다. 실제 iPhone/iPad 확인을 뜻하지 않습니다.
- 효과의 중독 중단·회복, 양쪽 직업 변경·원인 사망, 꼭두각시 면역, 과학자 유래 간접 획득 제한, 획득 수학자 예정 기상, 대상 부족 등은 로컬 규칙 테스트로 별도 확인했습니다. 이 네 파일이 해당 분기를 모두 수동 재현하는 것은 아닙니다.

## 구현 경계

- 두 직업은 공용 캐릭터 목록에 추가했습니다. 위 파일이나 특정 게임 구성에 종속되지 않습니다.
- 효과·밤 깨어남·정보 진실·징크스·저장/복원·되돌리기 판단은 Rust Custom Core가 담당하고, 웹은 그 결과를 표시합니다.
- 전도사는 중독과 별개인 능력 상실 효과를 사용합니다. 원인 전도사의 취함/중독 중에는 기존 효과와 토큰이 비활성화되고, 회복하면 재개됩니다. 원인 사망·직업 변경, 대상 직업 변경 때 효과와 토큰이 제거됩니다.
- 객실 청소부는 해당 밤의 확정 행동 기록에서 본인 능력으로 깨어난 사람을 중복 없이 셉니다. 타 능력 통지·초기 악팀 정보는 제외합니다. 과거 기록은 직업 변경 뒤에도 유지됩니다. 생존 대상이 두 명보다 적으면 행동을 생성하지 않습니다.
- 과학자 → 전도사는 금지하며 철학자·픽시를 거치는 우회 획득도 차단합니다. 일반 철학자·픽시는 전도사 능력을 얻을 수 있습니다.
- 꼭두각시는 전도사에게 영향받지 않습니다. 두 제품 징크스는 공식 징크스와 동일한 UI로 표시하되 내부 출처는 #251로 기록합니다.

## 재생성 및 로컬 검증

프로덕션 WASM 빌드 뒤 `node scripts/generate-issue251-acceptance-fixtures.mjs`로 파일을 재생성합니다.

```sh
cargo test -p clocktower-custom-domain --lib
pnpm --dir web build
pnpm --dir web exec vitest run --config vitest.custom.config.ts
PLAYWRIGHT_BASE_URL=http://127.0.0.1:10251/clocktower/ pnpm --dir web exec playwright test issue251-characters.spec.ts --workers=2
```

서버 시작·종료는 프로젝트 수명주기 관리자를 사용합니다. 이 검증들은 로컬 실행용이며 CI 범위를 확대하지 않습니다.
