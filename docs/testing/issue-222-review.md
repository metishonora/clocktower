## 순서 편집과 새 게임

1. Custom Scenario → JSON에서 불러온다 → 시나리오 파일을 선택한다.
2. 최종 검토에서 밤 행동 순서로 돌아간다. 좁은 화면은 첫날 밤/이후 밤 탭, 넓은 화면은 두 구획이다.
3. 이후 밤의 임프를 위로 이동한다. 첫날 밤 배열은 그대로이고, 수도사/임프 순서만 바뀐다. 이후 밤 기본값 복원을 누른다.
4. 시나리오 저장으로 JSON을 내려받고 다시 불러온다. 두 배열이 보존됐는지 확인한다.
5. 새 마도서 쓰기 → 7명 → 장의사·수도사·까마귀지기·성결자·처단자·탕녀·임프를 선택한다. 같은 순서로 1–7번 좌석에 배치하고 좌석 확정한다.

## 첫날 밤부터 셋째 밤

빠른 시작은 게임 파일을 불러온 후 마도서 이어 쓰기를 선택한다.

1. 악마의 속임수로 군인·시장·성자를 선택한다. 하수인/악마 정보를 공개하고 닫아 확정한다.
2. 낮 시작 → 발표 완료 → 공개 토론으로 → 지명 및 투표로 → 지명 종료 → 확정 → 다음 밤으로 진행한다. 제목은 2일차 밤이다.
3. 수도사는 1번을 보호한다. 임프는 3번 까마귀지기를 공격한다. 악마 공격 결과에서 3번 사망을 확인한다. 다음을 누르면 진행 탭에 까마귀지기가 표시된다. 대상 선택을 눌러야 마도서 선택 화면이 열린다.
4. 대상 선택 전에 저장 / 불러오기 → JSON 내보내기를 실행한다. 새로고침 후 현재 행동이 유지되고 정보가 저절로 공개되지 않는지 확인한다.
5. 내보낸 게임을 다시 불러오고 이어 쓴다. 까마귀지기로 1번을 선택해 공개하면 장의사 정보가 나온다. 닫고 다음 단계로 확정한다.
6. 최근 행동 되돌리기를 누른다. 임프 공격과 까마귀지기 후속이 함께 제시되는지 확인하고 되돌린다. 3번이 살아나고 임프 공격으로 돌아온다.
7. 이번에는 보호된 1번을 공격한다. 결과의 사망 없음을 확인하고 다음을 누른다. 낮 시작 후 2번 절차를 반복한다. 제목이 3일차 밤이고 수도사가 현재 행동이다.

## 구현과 검증 경계

밤 번호·입력 후보·시장 판단·승계·이발사 선택 수는 코어 응답을 소비한다. 밤 상태를 UI 카운터로 만들지 않는다. 정체 변경 통지도 코어의 기존 pending reveal 흐름을 사용하며 저장 후 공개한다. 복원 시 마지막 사건의 통지는 비공개 상태로 다시 제공한다.

자동화 검증과 사용자 인수는 구분한다. 개발 중 인앱 브라우저로 두 구획 표시, 이후 밤 이동, 기본값 복원을 직접 확인했다. Playwright의 390/820/1366 폭은 브라우저 viewport 검사이며 실제 휴대폰/iPad 검증은 아니다. 사용자 직접 인수와 실기기 검증은 아직 미확인이다.

세부 자동화 결과는 [구현 기록](../implementation/issue-222-progress.md)에 기록한다.

## 인수 중 발견한 정체 표시·알림 수정

- 낮에 처단자나 처형으로 악마가 죽어 탕녀가 승계하면, 좌석은 즉시 새 악마 아이콘으로 바뀌고 `악마임` 토큰을 유지한다. 낮에는 변경 알림 없이 진행할 수 있어야 한다.
- 다음 밤으로 넘어가면 저장 완료 후 탕녀에게 직업 변경 안내를 비공개 상태로 제공한다. 공개 버튼을 눌러야 새 악마 정보를 보여준다. 밤 전환 직후 새로고침·JSON 재가져오기에서도 안내를 복원한다.
- 밤 전환을 되돌리면 낮으로 돌아오며 알림이 사라진다. 다시 밤으로 진행하면 안내가 나온다. 승계 원인인 죽음을 되돌리면 탕녀로 복원된다.
- 주정뱅이 좌석은 보여준 마을주민 아이콘·이름을 표시한다. 좌석의 토큰 개수와 상세 표시 방식은 기존대로 유지한다. 낮·밤·지명 화면 및 파일 복원 후에도 같아야 한다. 좌석 상세에서는 실제 주정뱅이와 보여준 직업을 확인할 수 있다.
- 군인으로 알고 있는 주정뱅이는 임프의 공격을 막지 못한다. 화면 표시를 바꿔도 실제 직업과 능력 판정은 주정뱅이를 유지한다.

## 시장 공격 판단

시장을 공격 대상으로 선택하면 `시장이 사망` / `다른 플레이어가 대신 사망` 버튼이 나온다. 대신 사망을 고르면 마도서에서 대상 좌석을 선택한다. 원래 시장은 공격 대상으로 표시되고 대신 사망 대상은 별도로 강조된다. 초기화는 대신 사망 대상만 지우며, 취소는 시장 판단으로 돌아간다. 최종 선택 확정 후 공격 결과에서 실제 사망자를 확인한다.
