# #222 공격 결과 화면 누락 점검

2026-09-14. 사용자 첨부 게임을 읽고, 마지막 임프 공격 직전 기록으로 돌아가 실제 custom WASM/controller와 리뷰 서버 브라우저에서 재현했다. 최초 작업은 원인·영향 범위 점검이었다. 이후 사용자 요청으로 아래 수정 반영 항목을 구현했다. 첨부 게임과 진단용 테스트는 저장소에 추가하지 않았다.

## 재현

첨부 기록의 `phase-step-12`는 8번 임프가 1번 수도사를 공격한 사건이다. 코어에는 `nightAttack`, 대상 `player-1`, 사망자 `player-1`, `died: true`가 기록돼 있다. 직전 수도사 보호 대상은 2번이다. 같은 공격을 다시 실행하면 사망은 정상 반영되고 저장도 성공하지만, 마도서의 공격 결과 확인 없이 진행 탭의 `낮 시작`으로 이동한다.

## 구조적 원인

1. `actions/nightContracts.ts`의 `directNightAction`을 수도사, 다섯 악마, 피트 해그와 사망 후속 행동이 공유한다. `revealOpen: result`라는 값은 실제 진행자 결과 화면을 생성하지 않는다.
2. `FirstNightController.confirm()`은 입력용 handoff를 보존한 뒤, 정체 변경 통지가 있을 때만 notification으로 전환한다. 통지가 없으면 savedHandoff를 undefined로 만든다.
3. `CustomGrimoirePlay`는 handoff가 없어지는 것을 작업 종료로 처리해 진행 탭으로 전환한다. 같은 실행의 후속 행동이면 prepareCurrent가 곧바로 다음 선택을 시작할 수도 있다.
4. 타입과 `CustomGrimoireBoard`에는 result 상태/결과 패널이 남아 있지만, custom controller에서 result 상태를 만드는 경로가 없다. 단순히 result 상태만 되살려도 현재 패널은 선택 대상만 표시하므로 실제 사망·생존 결과 표시까지 연결해야 한다.
5. 코어의 확정 사건에는 실제 결과가 있다. 진행자 결과 확인과 플레이어 비밀 정보 공개를 별도 계약으로 다뤄야 한다. 공격 결과를 플레이어 RevealPayload로 만드는 방식은 맞지 않는다.

공식 TB의 `main.tsx`는 `악마 공격 결과`와 `finishTroubleBrewingAttackCheckpoint`를 명시적으로 연결한다. custom의 단순 대상 지정 계약을 공격에 재사용하면서 이 확인 단계가 빠졌다.

## 테스트 공백과 수정 방향

- 기존 #222 테스트는 사망·승계·후속 행동·복원을 확인했지만, 공격 직후 결과 패널에서 멈추는지를 확인하지 않았다. 기존 단순 지정을 즉시 종료하는 테스트는 이 동작을 요구하므로 결과 확인 여부를 행동별로 분리해야 한다.
- 다섯 악마의 공격에 진행자 결과 확인 계약을 선언하고, 코어의 확정 결과로 공격 대상·실제 사망자 또는 사망 없음을 표시한다. 다음 버튼을 누른 뒤 후속 행동/정체 통지/진행으로 연결한다.
- 저장 중·실패·재시도, 실제 사망·보호·반사·자살·승계, 후속 행동, 게임 종료, Undo, 복원을 이 결과 확인 경계에서 검증한다. 이미 확정된 공격을 다음 버튼으로 중복 실행하지 않아야 한다.
- 나머지 행동은 원본 흐름에 따라 직접 복귀/결과 확인/플레이어 통지를 각각 선언한다. 공통 controller에 캐릭터별 예외를 계속 추가하는 방식은 피한다.

## 추가 확인: 까마귀지기 진입 화면

사용자 후속 제보대로 까마귀지기 사망 시 진행 탭을 거치지 않고 마도서 대상 선택을 곧바로 연다. `ravenkeeper.learnCharacter`의 `completionContract.continuationEntry`가 `select`이고, `FirstNightController.prepareCurrent()`가 같은 execution의 continuation을 만나면 즉시 `beginSelection()`을 호출하기 때문이다.

이는 공격 결과 누락과 별개의 진입 정책 문제다. 코어에서 공격과 사망 후속이 같은 실행·Undo 단위라는 사실은, UI에서 대상 선택을 자동으로 열어야 한다는 뜻이 아니다. 공식 TB의 `finishTroubleBrewingAttackCheckpoint()`는 공격 결과를 닫고 진행 탭으로 복귀한다.

수정 기준은 `공격 확정 → 공격 결과 확인 → 다음 → 진행 탭의 까마귀지기 행동 → 대상 선택 버튼 → 마도서 대상 선택 → 진행 탭의 정보 공개`이다. 기존 실행 순서와 묶음 Undo는 유지한다. 결과 화면만 복구하는 것으로 끝내지 않고 후속 행동의 진입 화면도 별도로 선언해야 한다.

기존 다중 밤 테스트는 공격 직후 까마귀지기가 현재 action인 것과 저장·복원·정보 공개를 확인했지만, 최초 진입 시 진행 탭에 멈추고 `selecting=false`인지 확인하지 않았다. 이 검증을 추가해야 한다.


## 수정 반영

- 다섯 악마의 공격에 결과 확인 계약을 연결했다. 확정 사건의 공격 대상과 실제 사망자/사망 없음을 보여주고 다음을 기다린다. 시장 반사 시 선택한 대상과 실제 사망자를 구분한다.
- 까마귀지기와 이후 밤 후속 행동은 진행 탭에서 시작한다. 실행·Undo 의존 관계를 화면 자동 진입으로 해석하지 않는다.
- 마녀와 교환 없는 뱀 조련사의 결과 확인을 복구했다. 피트 해그의 실제 변신과 이발사의 실제 교환은 결과 확인 후 수신자별 비공개 통지를 제공한다. 무변경·교환 거절과 원래 직접 복귀하는 단순 지정은 직접 복귀한다.
- 저장이 성공한 뒤 결과 확인을 제공한다. 실패 시 재시도로 같은 결과를 복원한다. 다음 버튼은 사건을 다시 실행하지 않는다. 결과 확인 중 다음 행동을 선택하거나 실행할 수 없다.
- 새로고침·JSON 재가져오기 시 마지막 확정 사건으로 결과 확인을 복원한다. 결과 확인 여부를 파일에 별도 기록하지 않으므로, 다음 사건이 확정되기 전 다시 불러오면 같은 결과를 다시 확인한다. 플레이어 정보는 자동 공개하지 않는다.
- 기존 죽음·후속 행동의 묶음 Undo와 코어의 종료 판정 시점은 유지한다. 마지막 악마가 죽은 경우에도 먼저 공격 결과를 확인하고 밤 종료로 이어진다.
- 제품에 새로운 좌석 토큰이나 별도 결과 화면 디자인을 추가하지 않고 기존 마도서 결과 패널을 사용한다.

검증: custom 334개, 웹 integration 801개, #222 브라우저 10개 통과. 웹 production 빌드 성공. 브라우저는 390/820/1366 폭에서 공격 결과, 까마귀지기 진행 탭 진입, 정보 공개, JSON 복원과 묶음 Undo를 확인했다.

기존 첫날 밤 브라우저 회귀 62개 범위 통과: 최초 54개 통과 후, 마녀 결과 확인을 반영한 4개와 새 뱀 조련사 무교환 결과 4개를 실행해 8개 모두 통과했다. 웹 아키텍처 검사도 통과했다.
