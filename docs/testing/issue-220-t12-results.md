# #220 T12 후속 인수 수정 결과

2026-09-11. 적용 보정 강조, 중복 상태 칩 제거, 진행 중 배치 복귀 버튼 제거를 구현·검증했다. 쌍둥이 동선/Undo 변경은 사용자 답변 대기이며 구현하지 않았다.

## 반영한 변경

- 자동 보정 값에 BMR의 기존 선택 상태 CSS를 직접 공유했다. 별도 클릭 입력 없이 밤/낮 및 compact/desktop에서 적용 상태를 강조한다.
- 상세에 추가했던 생존/사망/중독/취함 상태 칩을 모두 제거했다. 원형 토큰, 진영/정체, 획득 능력, Core 상태와 기록은 유지한다.
- 진행 중 마도서의 배치 복귀 버튼을 제거했다. 다른 위치에 대체 초기화 버튼을 추가하지 않았다.

## 검증

- 기존 검사 기대를 최신 지시에 맞춰 수정 후 7개 실패를 먼저 확인했다. 수정 후 설정/사망 관련 UI 20개 통과.
- integration 전체 719개 통과. 이후 추가한 실제 쌍둥이 사건 연결 검사 1개 별도 통과. integration TypeScript 재검사 통과.
- production/BMR 브라우저 12개 통과: 320/390/820/1366px에서 실제 설정·보정·확정·낮·새로고침·처형·Undo 및 원본 대부 보정 ±1.
- 실제 1366px와 320px screenshot을 열어 기존 BMR과 동일한 선택 강조를 확인했다. 상세 상태 칩과 배치 복귀 버튼 부재는 실제 UI integration 검사로 확인했다. 물리 기기 및 모든 상태의 시각 대조를 완료한 것은 아니다.
- pnpm --dir web build, verify:pwa, git diff --check 통과. 최신 리뷰 자산은 JS IT9B7FgN / CSS DGmRv--w.

증거: [issue-220-t12-evidence](issue-220-t12-evidence). 기존 T11 기록은 당시 결과이며, 중독/취함 칩에 대한 기존 기대는 이번 사용자 지시로 대체한다.

## 쌍둥이 조사·제안

실제 Core 게임에서 minionInfo→demonInfo→assignTwin→learnTwin→dawn 순서를 확인했다. 지정과 통지는 별도 customActionConfirmed 사건이며, 통지의 result.relationshipEventId가 지정 사건을 정확히 가리킨다. 같은 소유자/능력 인스턴스도 이미 제공된다.

TB 정보 준비에는 informationFlow 및 자동 준비→공개 연결이 있으나 쌍둥이에는 연결되지 않았다. 공식 마도서 canonicalUndo에는 관련 사건 묶음이 있지만 custom canonicalUndo는 모든 사건을 하나씩 반환한다. 따라서 단순 숨김/탭 변경만으로 Undo까지 해결되지 않는다.

권장안은 기존 Core 단계·사건·저장 형식을 유지하고, 연속된 동일 쌍둥이 관계의 지정→통지에 화면 흐름 및 Undo 묶음을 연결하는 것이다. 중간에 다른 행동이 있으면 그것까지 되돌리지 않는다. 게임 전체 아키텍처 교체나 시나리오 순서의 웹 재작성은 필요하지 않다.

기존 spec에 Undo 단위를 유지한다고 명시돼 있어 변경 승인을 질문했다. 답변 전에는 이 부분을 구현하지 않았다. 쌍둥이 조사 테스트는 현재 Core 연결을 검증하는 것으로 즉시 공개/묶음 Undo가 구현됐다는 증거가 아니다.
