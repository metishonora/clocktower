# #220 직접 인수테스트

> 2026-09-11 수정 계획 v2 기준으로 기대 동선을 정정했다. [확정된 수용 조건 57개](../plans/issue-220-reuse-traceability.md)는 수정 구현 후 검증 대상이며, 현재 review 서버에서 모두 구현·통과됐다는 뜻이 아니다.

대상은 Production의 **Custom Scenario**다. 첫날 밤까지 연결한 BMR 테마 마도서를 검토한다. 과거 prototype 페이지 대신 서버 첫 화면에서 `Custom Scenario 선택`으로 들어간다.

아래 체크박스는 아직 사용자 판정 전이다. 실패하면 항목 번호, 사용 파일, 마지막 입력, 기대/실제 결과를 남긴다. 검토 서버: 리뷰 서버(검증 당시) (`preview`, 포트 10220, running/verified). 휴대폰/iPad는 이 주소에 접근 가능한 네트워크에서 사용한다.

## 1. 기본 흐름 — 먼저 10~15분

준비 파일: [01-basic.scenario.json](issue-220-manual/01-basic.scenario.json). 파일 선택 창에서 이 문서 옆 `issue-220-manual` 폴더를 연다.

- [ ] **A1 작성·불러오기** — 새 작성과 JSON 불러오기 두 선택을 확인한다. 준비 파일을 불러오면 중간 화면 없이 최종 검토로 이동해야 한다. 이름과 밤 순서를 수정하고 시나리오 JSON을 저장·재수입해 수정 내용이 유지되는지 본다. 시나리오 파일만으로 `마도서 이어 쓰기`가 생기면 안 된다. (C01–04, C09, C13)
- [ ] **A2 게임 설정** — 원본 준비 파일로 `새 마도서 쓰기` → 5명을 선택한다. 실제 배역은 처음에 비어 있어야 한다. **요리사 → 초공감자 → 시계공 → 독살범 → 임프** 순으로 선택하고 `직업 선택 확정` → 좌석 1~5를 차례로 눌러 같은 순서로 직업 토큰 선택 → `좌석 확정`. BMR 테마 설정 화면과 배치 화면에서 5좌석과 현재 행동을 사용할 수 있어야 한다. 모바일은 좌석을 먼저 누르면 하단 직업 선택판이 열린다. 다른 종류/총인원이 정원을 넘게 선택되지 않아야 한다. (C05–07)
- [ ] **A3 정보 공개** — 하수인 정보를 확인한다. 공개 중에는 이야기꾼 화면과 조작이 보이지 않아야 한다. `가리기` 후 다시 보기에서 같은 정보가 나와야 하고 `다음으로`에서 한 번만 진행해야 한다. 악마 bluff는 **군인·시장·성결자** 3개를 고른다. 2개만 고르면 확정할 수 없어야 한다. (C27–28)
- [ ] **A4 첫날 밤 끝까지** — 독살범은 4번 자신을 선택한다. 위 좌석 순서를 유지했다면 요리사 **1**, 초공감자 **0**, 시계공 **1**의 정상 계산값을 전달한다. 마지막에 Day까지 진행하고 낮 능력/다음 밤이 활성화되지 않는지 확인한다. 기록에서 요리사의 과거 정보는 여전히 1이어야 한다. (C15, C38)
- [ ] **A5 공개 중 새로고침·Undo** — 정보 공개 중 새로고침한다. 마지막 확정 지점으로 돌아오되 플레이어 정보가 저절로 공개되면 안 된다. 행동 하나를 확정한 뒤 `직전 행동 되돌리기`로 그 행동을 다시 진행할 수 있는지 본다. (C16, C37)
- [ ] **A6 게임 JSON 왕복** — 진행 중 상단 `저장 / 불러오기` → `JSON 저장` 후 같은 화면의 `JSON 불러오기`로 그 파일을 불러온다. 검토에서 이름을 바꾸면 이어 쓰기가 사라지고 정확히 되돌리면 복구되어야 한다. 이어 쓰면 같은 진행·이름·좌석·기록이 복원되어야 한다. 별도 좌석 배치를 사용했다면 그 배치도 비교한다. (C10–12, C34)
- [ ] **A7 자동 저장 대체** — A6 게임 파일을 검토한 뒤 `새 마도서 쓰기`로 설정을 편집한다. 확정 전에는 기존 저장이 유지되어야 한다. 플레이어 이름을 구별되게 바꿔 유효한 설정을 확정하면 교체 질문 없이 새 게임으로 시작한다. 새로고침해 새 게임이 남는지 확인한다. 이전 JSON을 가져와 이어 쓰면 그 파일의 기록으로 다시 대체되어야 한다. 시나리오 JSON 재수입은 새 identity이므로 이 검사에는 **게임 JSON**을 사용한다. (S1-a–d, S1-f)

- [ ] **A8 상단 유틸리티** — 설정/플레이 양쪽의 `새 게임`, `저장 / 불러오기`, `버그 제보`를 확인한다. 새 게임은 초기화 확인창을 열고, 취소는 현재 입력·진행을 유지한다. 확인하면 같은 시나리오의 빈 설정으로 이동하며 새 좌석 확정·저장 성공 전에는 이전 저장을 유지한다. 설정의 JSON 저장은 시나리오 파일이다. 제보 창 미리보기는 기본으로 이름·메모를 제거하고, 취소하면 진행 화면으로 돌아온다.
- [ ] **A9 진행 화면 세부** — 직업 아이콘/이름을 누르면 기존 상세가 열린다. 현재 플레이어·능력, 준비/획득 능력 표시, 금색 공개 버튼, 상태+직업명으로 간결해진 순서를 확인한다. 플레이어 이름·좌석은 목록 대신 현재 카드에서 확인하고, 획득 능력은 `철학자 · 세탁부`처럼 표시되어야 한다. 데스크톱은 카드와 순서 2열, 모바일은 세로 배치다. 악마 속임수 선택/무작위 추천과 모든 행동 버튼이 카드 밖으로 벗어나지 않아야 한다. `저장 / 불러오기`에서 최신순 기록과 당시 정보 다시 보기를 확인한 뒤 진행 탭으로 돌아온다. 진행 헤더에 별도 기록 버튼이 없어야 한다. 대상 입력은 마도서 좌석에서 선택하고, 일반 탭/상세/저장 이동은 현재 입력을 유지해야 한다.

## 2. 남은 복합 화면 — 우선 검토

각 파일을 첫 화면의 JSON 불러오기로 선택하고 `마도서 이어 쓰기`를 누른다. 준비 파일들은 승인된 #209 입력으로 만든 Setup 직후 게임이며 실제 WASM 전체 복원 검증을 통과했다. R 파일들은 같은 시나리오 ID를 사용하므로 이어 쓰면 해당 자동 저장 슬롯을 대체한다.

정보 공개는 공통으로 **정보 공개 → 가리기 → 다음으로** 진행한다. 대상/능력 선택이나 정보 준비 확정은 `확인`을 누른다. R1/R2/R4/R5의 악마 bluff는 **화가·백치천재·곡예사**를 선택한다.

## 3. 실기기·회귀 확인

- [ ] **C1 모바일/iPad** — 실제 기기의 Safari에서 A2–A6을 실행한다. 세로/가로 전환, 긴 배역 목록 스크롤, 좌석 선택, 모든 입력/확정 버튼 접근, 공개 화면 가리기를 확인한다. 글자가 잘리거나 가로 스크롤이 강제되지 않아야 한다. (C21)
- [ ] **C2 키보드** — 데스크톱에서 Tab/Shift+Tab으로 선택·공개·가리기 조작을 한다. 공개 중 배경으로 포커스가 빠지지 않고 가린 뒤 조작을 계속할 수 있어야 한다. (C21, C27)
- [ ] **C3 공식 게임 보존** — 같은 브라우저에서 TB와 SnV의 진행을 저장 → 커스텀 게임 진행 → 공식 화면으로 돌아가 각각 복원한다. 기존 공식 기록과 진행 위치가 유지되어야 한다. (C20)
- [ ] **C4 큰 후보 풀** — 새 작성에서 후보 25명을 선택하고 설정으로 이동한다. 후보 25명이 실제 배역에 자동 배치되지 않고 빈 선택에서 5–15인을 구성해야 한다. (C23)
- [ ] **C5 권장 수 부족** — A1의 8명 후보 시나리오는 권장 후보 수보다 작다. 경고만으로 저장·유효한 5인 Setup을 막지 않는지 확인한다. (C08)

저장장치 오류·손상 슬롯·늦은 비동기 응답·오래된 제안은 자동화로 별도 검사한 항목이다. 고장 주입은 위 일상 인수 동선에 포함하지 않는다. 아직 남은 세부 조합은 [테스트 결과표](issue-220-test-results.md)에 유지한다. 이 문서 작성 자체가 사용자 인수 통과를 뜻하지 않는다.


## BMR 테마 추가 인수

- [ ] 직업/마도서/진행/기록/저장/제보의 패널·선택 탭·버튼이 BMR 색을 사용한다.
- [ ] 좌석 편집판, 마도서 중앙 이동 버튼, 플레이어 상태 배지에도 보라색 SnV 테마가 남지 않는다.
- [ ] 설정의 직업 설명과 플레이어 상세에서 연 직업 상세가 BMR 밤/낮 테마를 따른다.
- [ ] 플레이어 공개는 BMR 전체 화면이며 `가리기`와 키보드 격리가 유지된다.
- [ ] Day 복원은 BMR의 밝은 낮 테마와 해를 표시한다. 작은 화면의 제목·혈월·되돌리기 버튼이 겹치지 않는다.


## 승인된 복귀·확정 동작 추가 인수 — 수정 구현 후 실행

- [ ] **D1 직업 확정 유지** — 직업 선택 확정 뒤 직업 탭과 좌석 화면의 뒤로 가기로 이동한다. 인원·악마·배역은 바꿀 수 없고 모든 직업 설명은 조회할 수 있어야 한다. 배역 구성 변경은 새 게임에서만 가능하다. (U02–U04, 결정 R1)
- [ ] **D2 배치 복귀 취소** — 첫날 밤 진행 중 `배치로 돌아가기`를 누르고 확인창을 취소한다. 현재 입력·대기 공개·진행과 자동 저장이 그대로여야 한다. (U12)
- [ ] **D3 배치 복귀·재시작** — 복귀를 확인하면 처음 설정한 인원·이름·Actual/Shown·좌석이 채워진 배치 화면이어야 한다. 배역 구성은 확정 상태로 유지하고 좌석을 수정한 뒤 확정하면 첫날 밤부터 새 게임으로 시작한다. 밤중 교환·획득·중독·사망을 새 Setup에 복사하지 않는다. (U12, 결정 R2)
- [ ] **D4 확정 전 새로고침** — 배치 복귀 후 좌석을 확정하지 않고 새로고침하면 이전에 저장된 게임이 복원돼야 한다. 새 좌석 확정·저장 성공 후에는 새 게임이 복원돼야 한다. 별도의 자동 저장 교체 확인은 없어야 한다. (U01/U12, S1)

저장 실패·재시도의 동일 Setup 사건 보존과 이전 writer의 늦은 저장 차단은 test 단계에서 별도 검증한다. 체크박스는 사용자 인수 결과가 생길 때만 변경한다.
