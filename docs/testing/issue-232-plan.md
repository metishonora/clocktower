# #232 복합 시나리오 인수 설계

## 합의와 기준

- 제품 기준: #231 / PR #243 병합 `ec92d37bd58532f52d7db506f307edb74e82af7a`.
- 2026-09-16 사용자 합의: 먼저 47개 캐릭터의 능력·분기 표를 작성하고, 함께 확인할 수 있는 사례를 최대한 담은 복합 시나리오와 게임을 만든다. TB 단독/SnV 단독/혼합 또는 전체 흐름/집중 분기라는 사전 분류와 할당량은 두지 않는다.
- 실제 배정 또는 합법적인 능력·정체 획득 후 능력의 효과를 관찰해야 한다. 후보 풀 포함은 능력 인수 근거가 아니다.
- 진행 경로가 충돌하면 같은 게임에서 선택을 바꾸거나 인과 Undo를 사용한다. 다시 시작할 비용이 큰 지점에는 명령으로 만들어진 중간 게임 파일을 제공한다.
- 자동화, 사용자 직접 인수, 실기기 확인은 각각 기록한다. 이번 준비 작업은 사용자 승인이나 실기기 확인을 대신하지 않는다.

## 구성 원칙

검증 표를 입력으로 후보 풀, 실제 15인 배정, 좌석, 두 밤의 명시 순서, 사전에 정한 선택과 기대 결과를 작성한다. 다섯 복합 게임을 초안으로 삼되 Core 검증과 누락 조사 결과에 따라 조정한다.

| 게임 | 연결할 사례 |
| --- | --- |
| G01 뒤바뀐 증언 | 시작 정보, 등록, 독살, 주정뱅이 정보와 수학자, 남작 분포, 집사 투표, 성자 종료 |
| G02 죽음의 계승 | 낮 처형과 장의사, 보호·시장·군인, 사망 정보, 임프·탕녀 계승, 광기·마녀, 이발사·연인 후속 |
| G03 거짓의 계산 | 보르톡스, 낮 능력·투표 기록과 이후 밤 정보, 재봉사 소진, 쌍둥이·돌연변이·얼뜨기와 종료 |
| G04 건너간 악마 | 철학자 획득·피트 해그 변경, 뱀 조련사, 현자–은둔자, 팡 구–탕녀, 이동 소진과 취함 |
| G05 죽어도 남는 힘 | 비고르모르티스의 사망 하수인·중독·능력 유지, 피트 해그 악마 생성과 강제 후속, 노 다시 이웃 중독과 효과 해제 |

확정 사건·사망·중독을 직접 주입하지 않는다. 현재 Production WASM의 명령 검증과 replay를 통과한 사건만 게임 파일에 쓴다. 생성기는 다음 행동·행동자와 입력을 명시하며 예상하지 않은 단계를 자동 선택하거나 건너뛰지 않는다. UI 검증과 사용자 인수는 불러온 파일에서 실제 선택·공개·확정을 수행한다.

기대 결과는 공식 캐릭터 설명·고정 Jinx 자료와 검토한 규칙에서 정한다. Core가 반환한 값을 그대로 기대값으로 복사하지 않는다. 선택 가능한 판단은 명시적으로 선택한 합법적 결과와 그 보존을 검증한다.

## 책임과 실행

규칙·확정 사건·현재 상태·후속 순서의 책임은 기존 Rust Core, 파일·세션·Undo의 책임은 기존 custom 계층에 유지한다. 인수 자료는 기존 앱 전용 시나리오 v2 / 게임 v5를 사용한다. 테스트 때문에 새 제품 조작이나 규칙 엔진을 만들지 않는다.

1. 47종 및 주요 분기 표를 작성하고 기존 #209/#220/#223/#225/#222/#213 증거를 연결한다.
2. 복합 게임을 실제 Core로 실행하며 입력·기대 결과·관찰과 중간 파일을 연결한다.
3. 같은 자료를 파일 재검증, 실제 WASM/IndexedDB/Undo 및 Production 브라우저 검사에서 사용한다.
4. UI의 입력·공개·다음 단계, #231의 PDF/직업 화면, 공식 게임 회귀를 확인한다.
5. 리뷰 서버와 다운로드할 파일, 짧은 절차·체크리스트를 제공한다. 사용자 결과와 실제 기기 여부는 확인 후 갱신한다.

오래된 명령, 변조 파일, 저장 실패·늦은 비동기 응답은 기존 자동화와 추가 오류 주입으로 확인한다. 게임 규칙상 정상·주요 비적용·상태 변경은 사용자 인수 항목으로 남긴다. 실제 iPhone/iPad 시스템 인쇄·오프라인은 #231의 명시된 공백을 이어받는다.

## 완료 기록

각 케이스의 결과, 실행 커밋·파일·환경, 사용자·실기기 확인, 결함과 재검증을 별도 보존한다. 자동화 통과를 사용자 통과로 변환하지 않는다. 차단 결함은 수정·재검증하고 실행하지 못한 범위는 이유와 함께 남긴다. 작은 핵심 회귀 묶음을 현재 CI에 명시적으로 연결한다. 최종 사용자 승인과 #191 인계는 인수 이후다.
