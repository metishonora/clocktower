# #232 인수 중 발견한 규칙 결함

## D01 장의사가 성결자·집착 처형을 놓침 — 수정·재검증

- 재현: G02의 `virgin-day`에서 9번 시계공이 4번 성결자를 지명해 처형된 뒤 둘째 밤 장의사까지 진행한다.
- 이전: 장의사 행동이 나타나지 않았다. 낮 사망 원인의 `Execution`만 찾아 성결자·집착 처형을 누락했다.
- 기대: 전날 처형으로 죽은 시계공을 공개한다. 마녀 지명 사망은 처형이 아니므로 대상이 아니다.
- 수정: 낮의 공식 처형 기록에 연결된 사망 사건으로 장의사의 자격·입력·정보·등록 근거를 일관되게 찾는다.
- 근거: [공식 Undertaker 규칙](https://wiki.bloodontheclocktower.com/Undertaker). 성결자에 의한 처형도 포함한다.
- 회귀: `issue232_regressions::undertaker_reads_virgin_and_madness_executions_but_not_witch_deaths`, G02.

## D02 기존 악마를 다른 악마로 바꾸면 임의 사망 판단 누락 — 수정·재검증

- 재현: `G05-new-demon.game.json`에서 14번 마귀할멈이 15번 비고르모르티스를 노 다시로 변경한다.
- 이전: 새 악마임에도 필수 사망 판단 없이 노 다시 공격으로 넘어갔다. 비악마→악마만 생성으로 취급했다.
- 기대: 악마→다른 악마에도 필수 임의 사망 판단을 제공한다. 사망 없음 선택은 그 밤 공격도 사망 없음으로 처리한다. 다음 밤에는 정상 공격이 가능하다.
- 수정: 실제 변경이 일어났고 새 캐릭터가 악마면 악마 생성 후속을 만든다. 이미 사용 중인 동일 캐릭터를 선택해 변경되지 않은 경우에는 만들지 않는다.
- 근거: [공식 Pit-Hag 운영 지침](https://wiki.bloodontheclocktower.com/Pit-Hag), 기존 악마를 새 악마로 바꾸는 경우를 명시한다.
- 회귀: `issue232_regressions::changing_an_existing_demon_also_requires_arbitrary_deaths`, G05의 후속 복원·사망 없음·다음 밤 현자 사망 경로.

두 수정은 #232 작업 브랜치에 있다. 별도 GitHub 수정 이슈는 아직 발행하지 않았다. 잘못된 이전 판정이 이미 확정된 파일은 재현 시 수정 전 체크포인트 대신 이 묶음의 새 파일을 사용한다. 과거 파일 migration은 추가하지 않았다.


## D03 긴 게임에서 행동 확정 지연 — 수정·재검증

- 재현 자료: 사용자가 전달한 ‘건너간 악마’ 게임, 4번째 밤·56개 확정 기록. 개인정보가 포함될 수 있는 첨부 파일은 저장소에 추가하지 않았다.
- 원인: 다음 행동 제안과 확정 상태 재생에서 각각 시작부터 모든 기록을 다시 검증했다. 반복 처리와 매 기록의 밤 순서 생성 비용이 기록 수에 따라 증가했다.
- 수정: Rust 내부에 최근에 검증한 기록과 상태 한 건만 보관한다. 시나리오와 모든 과거 사건 내용이 정확히 같을 때만 재사용하고, 새 사건은 기존 경로로 검증한다. 바뀐 기록과 되돌리기는 전체 재생한다. 저장 형식과 규칙 결과는 바꾸지 않았다.
- 측정: 동일 로컬 Node/WASM 환경에서 56개 기록의 다음 행동 제안 약 57–60ms → 8–10ms. 실제 컨트롤러와 화면을 포함한 확정 측정은 약 174ms → 64ms. iPad 실기기 수치는 아니다. 파일을 처음 불러올 때는 여전히 전체 검증한다.
- 동등성: 사용자 파일의 1–56개 모든 기록 구간과 다음 행동 제안 결과가 수정 전후 동일했다. 기존 G03 자료를 사용해 추가·되돌리기·다른 게임·과거 결과 변조·잘못된 사건 추가도 확인한다. 새 수동 인수 항목은 추가하지 않는다.
