# #237 프로토타입 → 프로덕션 UI 점검

점검일: 2026-09-20. 최초 점검의 불일치 8개는 후속 요청으로 수정했다.
아래 최초 점검 기록은 이력을 위해 보존하며, 최신 상태는 마지막 후속 수정 절을 참조한다.

## 기준과 범위

- 최종 시각 기준: `../issue-237-prototype/web/src/prototypes/issue237/`의
  `CharacterReviewPrototype.tsx`, `prototype.css`, `fixtures.ts` (14개 장면).
- 이후 승인된 동작: [구현 결정 기록](issue-237-carousel.md).
- 프로덕션: 이 작업 트리의 `web/src/grimoire-custom/` 및 공유 UI.
- 검토 도구, 고정 이름/좌석/예시 수치, 폐기한 새 악마 통지 장면은 이식 대상이 아니다.
- 최초 변경은 사용자가 지적한 과학자 부여능력 토큰과 그 아래 중복 문구에 한정했다.
  이후 사용자가 남은 차이도 수정하도록 요청하여 아래 8개 항목을 반영했다.

## 이번에 수정·검증한 항목

과학자가 야경꾼 능력을 준 경우 상세 토큰은 위 `야경꾼 능력`, 가운데 야경꾼
아이콘, 아래 `과학자가 부여함`이다. 프로토타입의 긴 토큰 문구용 스타일을 적용했다.
비활성 상태의 X는 유지한다. 같은 과학자 토큰이 표시하는 능력에 한해서 아래
`획득 능력 · 야경꾼` 같은 중복 문구를 숨긴다. 픽시 등 다른 출처의 능력 표시는
이번 요청으로 제거하지 않는다.

원인: `customPlayerTokens`가 능력명/출처를 토큰 상하단에 잘못 배치했고,
`과학자가 부여함`은 설명 필드에만 있었다. 상세 창은 토큰과 별개로 모든 능력
부여를 다시 나열했다. 프로토타입의 긴 하단 문구 스타일도 이식되지 않았다.

수정 파일:

- `web/src/grimoire-custom/customPlayerPresentation.ts`
- `web/src/grimoire-custom/CustomGrimoireBoard.tsx`
- `web/src/grimoire-custom/customGrimoirePlay.css`
- `web/test/issue237Carousel.test.tsx`

차이 목록이다.

## 검증 기록과 제한

- `pnpm --dir web build` 성공.
- 통합 테스트 타입 검사, `check:architecture`, `git diff --check` 통과.
- `issue237Carousel`, `issue237Nightwatchman`, `issue237Voting`, `issue232TokenLabels`:
  4개 파일, 23개 테스트 통과.
- 최신 검토 서버에서 Playwright로 과학자 토큰을 390px/1280px,
  활성/비활성 총 4가지 상태로 검증: 상하 문구·아이콘·X·중복 문구 제거·문구 너비.
  모바일 활성/비활성 스크린샷도 직접 확인했다.
- 인수 파일은 별도 임시 브라우저 컨텍스트에서 읽었다. 정적 GET 외 요청과 외부
  요청은 차단했으며 사용자 브라우저 저장 상태를 변경하지 않았다.
- 추가로 10개 fixture의 진입 화면을 캡처했으나, 일부는 이전 행동의 결과/공개
  대기 화면이다. 이를 14개 장면 전체의 시각/동작 검증 완료로 간주하지 않는다.
- 검토 서버는 최신 dist 및 참조 자산 일치가 확인됐고 `keep=true`로 유지한다.

## 후속 수정 — 남은 차이 반영

사용자의 `남은 차이도 수정해` 요청에 따라 위 8개 항목을 수정했다.

- 꼭두각시 초기 선택: 직업 상세 위쪽 소형 드롭다운, `꼭두각시가 믿는 직업`,
  비활성 `선택 필요` 옵션, 선택 즉시 반영. 기존 열기구 보정 버튼과 함께 배치한다.
- 열기구: 진행 화면과 대상 선택 마도서에서 `직전 정보`를 표시한다. 처음은 `없음`.
  확정 이벤트의 대상·등록 유형을 읽으므로 이후 직업 변경으로 과거 유형이 바뀌지
  않는다. 능력 인스턴스와 가장 출처를 구분하며, 현재 행동 결과를 직전 정보로
  재사용하지 않는다. 플레이어 비밀 공개에는 이 이야기꾼용 정보가 들어가지 않는다.
- 야경꾼 `능력 없음`, 열기구 `알아냄`, 꼭두각시 `꼭두각시입니다`로 토큰명 복원. 이후 사용자 검토에서 야경꾼은 사용 소진을 명확히 드러내도록 `능력 사용함`으로 변경했다. 내부 `noAbility`와 규칙 처리는 유지한다.
  신규 직업별 매핑만 바꿔 기존 TB/SnV 토큰명을 보존한다.
- 픽시 `집착`은 프로토타입과 같은 금색 assignment 토큰으로 표시한다.
- 중간 생성 꼭두각시: 정상 진행 UI 안에서 믿는 직업 선택 → `본인에게 변경 직업
  공개` → 이야기꾼 화면으로 복귀 → `악마에게 공개`. 별도 일반 확인/마도서 통지
  화면을 거치지 않는다. 공개 전에 저장을 완료하며, 저장 실패 시 비밀을 열지 않는다.
  재시도·재접속 시도 명시적인 공개 버튼을 유지한다. 다음 수신자에게 자동 공개하지
  않고, 마지막 통지가 끝날 때까지 진행 목록의 현재 행동도 유지한다.
- 새 악마 과학자: 부여 대상에 좌석·이름·실제 악마 직업을 표시하고 프로토타입의
  대상 상자/드롭다운/강조된 확정 버튼 스타일을 적용한다. 다중 악마 대상 선택은
  이후 별도로 승인된 기존 기능을 유지한다.

기존 도메인 규칙, 저장 포맷, 능력 소유권은 변경하지 않았다. UI는 확정 기록을
표시하고 기존 컨트롤러의 저장·수신자별 공개 절차를 사용한다. 프로토타입 코드를
프로덕션에 import하지 않고 기존 공유 UI와 프로덕션용 표현 어댑터를 사용했다.

### 후속 검증

- 최종 `pnpm --dir web build`, 통합 테스트 타입 검사, 아키텍처 검사 통과.
- 기존 관련 테스트 6개 파일, 71개 통과. 꼭두각시 정상 공개/저장 실패/재시도/재접속,
  토큰의 기존 직업 비영향, 열기구 출처·과거 등록 유형·기록 제거를 포함한다.
- 390px/1280px 실제 브라우저에서 꼭두각시 초기 선택·본인 공개·악마 공개,
  새 악마 과학자 부여, 열기구 진행·대상 선택 화면을 검증했다.
- 본인 공개에 꼭두각시 정보가 없고, 닫은 뒤 악마 공개를 별도로 눌러야 하는 것을
  확인했다. 악마 통지 중 마도서 복귀 버튼도 잠긴다.
- 토큰 변경 및 화면 스크린샷을 별도 임시 브라우저 컨텍스트로 확인했다.
  전체 14개 장면의 모든 규칙 분기를 새로 인수 테스트한 것은 아니다.
