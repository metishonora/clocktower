# #220 T10 구현 기록

2026-09-11. 승인된 [spec](../specs/issue-220-custom-grimoire.md), [plan v3](../plans/issue-220-custom-grimoire-plan-v3.md)의 T10 및 T9 공개 실패를 수정했다. 준비 단계의 Red와 후속 기대값 검토는 [테스트 준비 기록](../testing/issue-220-t10-test-preparation.md)에 보존한다. 최종 실행 결과는 [검증 보고서](../testing/issue-220-t10-results.md)를 따른다.

## 입력과 진행 연결

- 세탁부·사서·수사관은 마도서 대상과 보여줄 캐릭터만 입력한다. 정답 플레이어 및 범용 등록 조합 질문을 제거했다. Core는 실제 대상 정체를 우선 사용하고, 원본 TB처럼 필요한 등록 출처를 좌석 순서로 결정한다. 중독/취함의 임의 정보에는 가상의 정답/오답 표식을 만들지 않는다. 명시적 등록을 포함한 기존 canonical 사건은 계속 검증·재생한다.
- 부분 선택과 최종 확정은 같은 Core 허용 조합에 연결했다. 첫 대상만 선택했을 때 나머지 유효 좌석을 흐리게 하지 않으며, 불가능한 조합 또는 오래된 부적합 draft로 진행 탭에 복귀하지 못한다.
- Core scheduler는 시나리오 정규 순서를 유지하면서 같은 소유자의 준비→전달을 마친 뒤 다음 소유자로 이동한다. 실제 사서와 주정뱅이 사서, 획득 능력의 owner/occurrence를 분리한다. 구 버전에서 여러 소유자를 먼저 준비한 저장 기록은 replay 전용 호환 경로로 읽고 새 명령에서는 그 순서 우회를 허용하지 않는다. 변경 전 WASM으로 만든 `legacy-duplicate-preparations.json`을 회귀 자료로 보존했다.

## 원본 정보 화면과 판정

- TB scalar 결과 및 팀 취급 표현을 공용 view로 추출하고 실제 원본 호출자와 custom에서 함께 사용한다. 요리사·공감능력자는 선/악 버튼으로 판정하고 Core 결과를 표시한다. 요리사의 쌍별 등록 출처는 유지하며 동일 결과에 서로 다른 등록 근거가 있는 후보를 합치지 않는다.
- 점쟁이의 착각 지정과 능력 사용을 나눴다. 착각 대상은 선한 플레이어 또는 선으로 등록 가능한 첩자이며 Core가 등록 근거를 공급한다. 실제 능력의 은둔자 악마 여부는 원본처럼 마도서에서 결정하고, 진행에 돌아오면 결과를 표시한다.
- 혼합 시나리오의 재봉사에는 팀 취급과 결과, 시계공에는 직업 분류 취급과 결과를 연결했다. 중복 결과 선택이나 모든 직업을 나열하는 범용 UI를 제거했다. 결과 계산은 Core만 수행한다.
- 사용자의 후속 결정에 따라 제목은 **‘이번 판정의 XXX 취급’**으로 통일했다. ‘실제 정체’ 같은 간접 표현 대신 해당 판정값인 **선/악** 또는 **주민/외지인/하수인/악마**를 표시한다. 선/악 버튼 순서 변경 요구로 해석하지 않는다. 중독·취함·보르톡스에는 의미 없는 등록 선택을 표시하지 않는다.
- Undo와 기록은 내부 action ID 대신 직업·행동·대상을 요약한다. 저장 사건과 Undo 단위는 유지한다.

## 공개 화면과 실제 호출 경로 정정

- 악마 공개 아이콘에 원본 64px 크기를 적용했다. role 공개 portal의 box model과 가용 폭을 연결해 320px 세레노버스/정체 변경 및 데스크톱 쌍둥이 넘침을 수정했다.
- 앞선 첩자 기준인 `TroubleBrewingLiveGrimoire.revealMode`는 실제 TB production 호출 경로가 아니었다. `main.tsx`의 `activeSpyRevealPayload`가 잠긴 일반 마도서를 보여주는 경로를 브라우저에서 확인하고 R29를 정정했다. 원본은 비활성 utility/탭, 일반 좌석과 토큰 badge, 중앙 **확인 완료**, 좌석 클릭 후 토큰 상세 조회를 제공한다.
- 실제 TB 잠금 경로와 custom이 `SpyGrimoireView`를 함께 사용한다. 커스텀은 공개 payload만 전달하며 토큰 조회만 허용한다. 편집 및 현재 Storyteller 상태 접근은 추가하지 않았다. 토큰 중복 개수, 사망 표시, 상세 닫기 후 포커스도 기존 표현을 사용한다.
- 마지막 browser 검사에서 공개창 기본 grid 스타일이 첩자 shell을 축소해 데스크톱 좌석을 겹치게 하는 CSS 충돌을 발견했다. 첩자 backdrop 선택자 우선순위와 shell 폭을 바로잡고 **15개 모든 좌석의 실제 클릭 가능성**을 검사에 추가했다. 숨겨진 원본 기준을 잘못 사용한 검사와 실제 제품 실패를 구분해 기록했다.

아키텍처를 교체하지 않았다. custom Core/official 경계, allowlisted 공개 payload, canonical 기록·자동 저장 구조, JSON 및 Undo 계약을 유지하면서 projection과 표현 연결을 수정했다. 새 UI를 무단 승인으로 간주하지 않았으며 혼합 직업 판정 표현은 사용자 확인 후 반영했다.
