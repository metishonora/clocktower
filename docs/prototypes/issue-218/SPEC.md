# #218 · 마도서 콘솔 프로토타입 스펙

2026-09-09 사용자 피드백을 반영한 최신 기준. 이 문서가 이전 스펙과 v2/v3 제작 기록보다 우선한다. 기존 시안은 예시이며 최종 디자인 승인이 아니다. **다음 작업은 컴포넌트별 범위·중요한 UI 결정을 먼저 확인하는 단계이며, 전체 화면의 일괄 제작 승인이 아니다.**

## 현재 판단과 우선순위

- v2는 “갈색 배경에 UI”, v3는 가시성이 나쁘고 제공한 스케치보다 못하다는 피드백을 받았다. 두 시안 모두 채택된 디자인으로 취급하지 않는다.
- 먼저 진행 탭의 이야기 표현을 검토한다. 배치·아이콘·선택지의 디자인은 다음 단계로 미룬다. 기존 시안은 비교 자료로 보존한다.
- 가독성과 기존 콘솔의 실제 조작을 우선한다. 분위기를 살리기 위해 정보 대비나 이름·직업(배역)·상태·입력 값의 식별성을 희생하지 않는다.

## 시각 방향과 레퍼런스의 역할

- 뉴시나리오 선택 화면의 사악한 마도서 분위기는 유지하되, 화면을 물리적인 책으로 만드는 데 집중하지 않는다. 펼친 책 테두리·중앙 접힘·구겨진 종이·양피지 질감을 필수 재료로 삼았던 이전 지침은 해제한다.
- **3번 [The Boat](https://www.sbs.com.au/theboat/)**를 진행 탭의 우선 레퍼런스로 삼는다. 이야기와 시각 표현이 함께 진행되는 방식을 참고하여 스토리텔링으로 분위기를 살린다. 구체적인 배경·서체·삽화·전환 동작은 아직 확정하지 않는다.
- **1번 [Potion Craft](https://www.potioncraft.com/)**는 이후 아이콘·배치·선택지 표현을 논의할 때 참고한다. 이번 진행 본문에 해당 레퍼런스의 종이 질감이나 선택 UI를 일괄 적용하지 않는다.
- 사용자 스케치는 정보의 단순함과 읽기 쉬운 구성의 비교 기준으로 유지한다. 스케치 외형 자체가 최종 디자인은 아니다.
- 이름과 직업(배역)을 강조한다. 상태와 조작 가능한 텍스트도 구별하되 구체적인 표현은 해당 컴포넌트 검토에서 정한다. 색상만으로 정보를 구별하지 않는다.
- 기존 #205 시나리오 편집 화면의 승인 사항은 유지한다.

## 컴포넌트와 문구의 기준

- **들어갈 컴포넌트·표시 정보·조작·용어는 기존 콘솔 UI를 기준으로 선정한다.** 기존 v2/v3 프로토타입에 들어 있다는 이유만으로 필수 요소로 간주하지 않는다.
- 컴포넌트를 논의하기 전에 해당 기존 콘솔 화면과 조건별 상태를 확인하고, 가져올 요소·이야기형 표현으로 바꿀 요소·추가 또는 제거하려는 요소를 사용자에게 보여준다. 새 기능이나 패널을 임의로 보태지 않는다.
- 기존 진행 UI의 단계 제목·경과 시간·현재 행동·행동자/배역/상태·필요한 입력과 조작·단계 개요, 이벤트 로그의 기록·최근 이벤트 되돌리기·오류/경고 등을 원본과 대조한다. 이는 확인 목록이며 모두를 첫 시안에 넣으라는 결정은 아니다.
- 분위기 설명, 장식용 부제·문구, 자명한 조작 안내, 같은 상태를 되풀이하는 라벨을 임의로 추가하지 않는다. 상태 이해·판단·입력 검증·오류 복구에 필요한 문구만 해당 상황에 표시한다.
- 이야기 본문은 실제 행동·대상·전달 정보·결과를 표현한다. 같은 정보를 별도 설명문이나 카드에 다시 풀어 쓰지 않는다. 서술 표현으로 의미나 정보량이 달라진다면 제작 전에 확인한다.
- 검토용 설명과 상태 전환 도구는 제품 화면 밖에 둔다.

관련 기존 UI 소스: `web/src/shared-ui/PlayPresentation.tsx`, `web/src/features/trouble-brewing/TroubleBrewingProgress.tsx`, `web/src/sectsAndVioletsLivePhase.tsx`, `web/src/features/event-log/EventLog.tsx`. 각 단계에서는 해당 기능의 실제 기존 화면과 연결된 컴포넌트까지 확인한다.

## 제작·확인 절차

`prototype` 스킬의 원칙인 “작업 전에 다음 내용을 사용자에게 제시하고 명시적인 확인을 받는다”를 따른다. 스킬 원본: `/Users/sg/.agents/skills/prototype/SKILL.md`.

1. 컴포넌트 하나 또는 서로 분리할 수 없는 작은 흐름 하나를 논의한다. 해당 화면·상태·사용자 흐름, 기존 UI에서 바꿀 부분, 답이 필요한 중요한 UI·상호작용 결정을 제시한다.
2. 사용자에게 명시적으로 확인받은 범위와 결정만 격리된 프로토타입으로 만든다. 사소한 구현 세부사항까지 같은 위계로 묻지 않되, 미결 UI 결정을 에이전트의 선호로 확정하지 않는다.
3. 해당 컴포넌트의 사용자 검토를 받은 뒤 다음 컴포넌트로 넘어간다. 새 중요한 UI·상호작용 문제가 생기면 먼저 질문한다.
4. 승인·미결·기각된 결정을 구분하여 기록한다. 전체 기능 스펙이나 이전 시안 제작 허가를 다음 전체 화면 제작 승인으로 해석하지 않는다.

### 다음 논의 대상과 미결 사항

- 우선 대상: 진행 본문. 현재 문장 → 완료 → 다음 문장의 작은 흐름을 첫 검토 범위로 제안한 상태이며, 구체적인 화면·상태·흐름은 사용자 확인 전이다.
- **본문 누적형과 장면 교체형 중 어느 방식을 사용할지는 미정**이다. 앞선 선택 질문은 답변되지 않았으며, 이번 스펙 업데이트 요청을 선택 또는 제작 승인으로 간주하지 않는다.
- 기존 콘솔의 어떤 요소를 첫 컴포넌트에 담을지, 본문·이름·배역·조작을 어떻게 구별할지, 분위기를 담을 배경/삽화와 전환의 정도는 이후 순서대로 논의한다.
- 배치·아이콘·선택지·공개·저장 화면은 이번 진행 본문 검토와 함께 재제작하지 않는다. 기능 요구는 아래에 유지하되 각 단계에서 범위를 확인한다.

## 화면 구조와 기존 컴포넌트 배치

이야기 표현이 기존 진행 및 이벤트 로그 화면을 대체하고, 별도의 배치 화면과 저장 화면이 필요하다는 기능 요구는 유지한다. 아래는 전체 검토 대상의 기능 대응표이며, 위치와 구체적인 표현은 해당 컴포넌트를 논의할 때 확인한다.

| 기존 기능 | 대응할 영역 / 검토 사항 |
| --- | --- |
| 좌석·플레이어·배역·생사·토큰 | 배치 영역 |
| 선택한 플레이어의 상세·메모·상태 수정 | 배치와 연결된 상세 영역 |
| 현재 행동·대상 선택·정보 입력·전달 | 현재 진행 영역. 입력·선택의 형태는 후속 검토 |
| 진행 순서 | 기존 단계 개요와 대조해 표시 방식 검토 |
| 완료 행동·이벤트 로그 | 과거 기록. 본문 누적 여부와 접근 방식은 미정 |
| 단계 전환·되돌리기 | 기존 동작을 기준으로 위치·표현 확인 |
| 기기 저장·파일 저장·불러오기 | 별도 저장 화면 |

- 데스크톱 좌측 배치·우측 진행, 모바일 하단에서 별도 배치를 꺼내는 구성은 이전에 논의한 안으로 보존한다. 진행 본문 확정 이후 배치 단계에서 다시 검토한다. 모바일의 물리적인 종이 모양은 필수 조건이 아니다.
- 배치 영역을 닫거나 저장 화면에서 돌아와도 작성 중인 입력과 진행 맥락을 유지한다.
- 문장 안의 단순 선택, 문단 아래의 복잡한 선택은 이전 검토안으로 보존하되 확정 형태로 강제하지 않는다. 선택지 UI는 다음 단계에서 기존 콘솔과 1번 레퍼런스를 대조하며 확인한다.

## 배치와 진행의 연결

- 현재 행동자와 선택 대상이 배치와 본문 양쪽에서 함께 강조된다.
- 본문의 이름으로 해당 인물을 찾고 상세를 확인할 수 있다.
- 대상 선택 중 배치의 플레이어를 눌러 선택할 수 있다.
- 모바일 배치 영역에서 선택할 때도 어떤 행동의 대상을 고르는지 확인할 수 있다.
- 인물 상세에서 예시 이름·배역·생사·토큰·메모를 수정해 기존 조작의 수용 방식을 검토한다. 새 규칙이나 도메인 동작은 구현하지 않는다.

## 기록과 실수 복구

- 현재 문단과 완료된 문단을 구별하되 과거 기록도 충분한 대비로 읽을 수 있게 한다.
- 이름·배역·상태와 조작 가능한 이름은 읽고 구별할 수 있어야 한다. 굵기·아이콘·표식 등 구체적인 표현은 컴포넌트별로 확인한다.
- 기록에는 행동 당시 이름·배역·선택·결과를 보존한다. 이후 현재 배치가 바뀌어도 과거 문장의 의미가 바뀌지 않는다.
- 낮·밤을 장 단위로 묶어 접기 및 장 이동, ‘현재 진행’ 복귀를 검토한다. 첫날 밤 이외의 기록은 탐색용 정적 예시다.
- 되돌리기 전에 영향을 받는 기록과 상태를 구체적으로 보여준다.

## 플레이어 정보 공개

- 공개 중에는 이야기꾼 본문, 데스크톱 배치, 모바일 배치 진입부, 메모 및 검토 도구를 숨긴다.
- 정보 공개 → 가리기 → 이야기꾼의 명시적인 전달 완료·복귀 동작을 거친다. 가리기만으로 비공개 배치가 바로 드러나지 않는다.
- 다시 펼치기와 이미 전달한 정보 확인을 검토한다.

## 저장 화면

- 기기 저장과 파일 저장·불러오기를 시각적으로 구분하고 ‘파일로 저장’, ‘불러오기’ 같은 명확한 행동명을 유지한다.
- 저장 시점, 저장/불러오기 결과, 기존 진행을 바꾸는 확인 상태를 예시로 검토한다.
- 실제 게임 저장·불러오기 및 저장 계약은 연결하지 않는다. 프로토타입의 저장 피드백은 시뮬레이션임을 검토 도구와 저장 화면 주변의 별도 검토 안내에 명시한다. 제품 화면과 검토용 설명은 구분한다. 실제 연결은 #205에서 수행한다.

## 전체 기능의 후속 검토 목록 (한 번에 제작하지 않음)

1. 데스크톱 배치+진행과 독립 배치 화면.
2. 모바일 배치 영역 열기·대상 선택·복귀.
3. 플레이어 상세, 생사·토큰·메모 수정 및 현재 상태 강조.
4. 하수인 정보 공개 → 악마의 속임수 세 가지 선택 → 정보 공개 → 요리사 및 점쟁이의 예시 입력·대상 선택.
5. 완료 기록 확인, 장 탐색, 현재 진행 복귀 및 되돌리기. 기록 누적 방식은 미정.
6. 플레이어 공개, 가림 및 이야기꾼 복귀.
7. 별도 저장 화면과 저장·불러오기 확인/피드백 예시.
8. 많은 인원·토큰, 긴 이름, 여러 대상 선택, 좁은 모바일 및 데스크톱에서의 가독성·조작 가능성.

## 범위 및 완료 판단

- 격리된 프런트엔드 시안과 예시 데이터만 사용한다. 프로덕션 UI·규칙·데이터 모델·저장 계약을 변경하지 않는다.
- 첫날 밤 이후 런타임이나 새 캐릭터 능력을 추가하지 않는다. TB/SNV 전체 테마 적용은 별도 범위 합의가 필요하다.
- 확인받은 프로토타입 범위에서 데스크톱/모바일 조작 확인, 관련 웹 빌드, prototype_reviewer 사전 검토 후 사용자에게 제시한다. 프로토타입용 테스트를 작성하거나 기존 자동화·회귀 테스트를 실행하지 않는다.
- 본 문서의 업데이트는 프로토타입 제작 또는 시각 결과의 승인이 아니다. 컴포넌트별로 사용자 확인을 거친 뒤 제작하며, 최종 승인된 결정과 미결 사항을 구분하여 #205로 넘긴다.
